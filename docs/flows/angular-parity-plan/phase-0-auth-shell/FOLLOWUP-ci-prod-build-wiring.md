# Follow-up: wire the production build (and Task 5's guard) into CI

**Status:** open — deferred out of Phase 0 (infra / cross-repo scope)
**Raised by:** Phase 0 whole-branch review, 2026-09-08
**Severity:** important — the deployed frontend bundle is currently built from placeholder config

## Problem

Phase 0 Task 5 added `frontend/scripts/lib/assert-prod-api-base-url.mjs` and wired it into
`frontend/scripts/build-env.mjs`, which runs from the `prebuild:prod` npm hook. Nothing in CI
invokes that path, so:

1. **`.github/workflows/frontend.yml`** (the `Build` step) runs `npm run build`
   (= `ng build`), **not** `npm run build:prod` (= `ng build --configuration production`,
   whose `prebuild:prod` hook runs `build-env.mjs`). So `build-env.mjs` — and therefore
   `assertProdApiBaseUrl` — **never executes in CI**.

2. The Angular `production` configuration (`frontend/angular.json`) does a `fileReplacements`
   swap to `src/environments/environment.production.ts`, which is a **committed placeholder**:
   `apiBaseUrl: ''`, every `cognito.*` empty, `disableAuth: false`. `build-env.mjs` is what is
   supposed to overwrite that file at build time from env vars. Because it never runs, a
   production-configuration build ships empty config, and `createUserPool()` throws on the first
   `Auth` injection in the browser.

3. Even if CI switched to `npm run build:prod`, it would fail `build-env.mjs`'s `REQUIRED`
   check: the workflow's `Build` step exports **`VITE_*`** names
   (`VITE_API_BASE_URL`, `VITE_COGNITO_REGION`, …) but `build-env.mjs` reads **`NG_APP_*`**
   names (`NG_APP_API_BASE_URL`, `NG_APP_COGNITO_*`).

Net effect: the guard that was supposed to "fail the prod build on an empty or local API base
URL" cannot fire in the pipeline that actually builds the app, and the artifact CI uploads is
mis-configured.

## Fix outline

In `.github/workflows/frontend.yml`, `Build` step:

- change `run: npm run build` → `run: npm run build:prod`
- rename the `env:` keys `VITE_*` → `NG_APP_*` (values unchanged — still
  `${{ inputs.api_base_url || '' }}` etc.):

  | old | new |
  |---|---|
  | `VITE_API_BASE_URL` | `NG_APP_API_BASE_URL` |
  | `VITE_COGNITO_REGION` | `NG_APP_COGNITO_REGION` |
  | `VITE_COGNITO_USER_POOL_ID` | `NG_APP_COGNITO_USER_POOL_ID` |
  | `VITE_COGNITO_CLIENT_ID` | `NG_APP_COGNITO_CLIENT_ID` |
  | `VITE_COGNITO_DOMAIN` | `NG_APP_COGNITO_DOMAIN` |
  | `VITE_COGNITO_REDIRECT_URI` | `NG_APP_COGNITO_REDIRECT_URI` |

- for non-deploy CI runs that legitimately have no real API URL, either skip the prod build on
  those runs or pass `ALLOW_LOCAL_API_URL=1` deliberately (that is the escape hatch
  `assertProdApiBaseUrl` provides).

## Things to check before doing it

- **`workflow_call` inputs are unchanged** (`api_base_url`, `cognito_*`), so the caller in the
  private `BlueFin605/home` repo (`deploy-*.yml`) should not need changes — **confirm** it only
  passes those inputs and consumes the `frontend-build` artifact, and does not itself run
  `ng build` / set `VITE_*`.
- Grep the repo for any remaining `VITE_` / `import.meta.env` usage in `frontend/src` — the
  Angular app should be fully on `NG_APP_*` / generated `environment*.ts` now, but verify
  nothing else reads the Vite names.
- `frontend/src/environments/environment.production.ts` is generated by `build-env.mjs`; decide
  whether it should stay committed as a placeholder or be `.gitignore`d (committing it is what
  lets a plain `ng build --configuration production` "work" with empty values — which is the
  trap here).
- `LOCAL-DEV-GUIDE.md` (repo root) still documents a `VITE_COGNITO_ENDPOINT` block for the
  React/Aspire stack; relabel it so the `VITE_*` vs `NG_APP_*` split is obvious to whoever
  picks this up.
